Why FinOps is different at a card issuer

Regulated financial services
PCI DSS scope

Tag the cardholder data environment (DataClassification=pci) so its cost is visible on its own. Savings changes inside it go through security review first.

Resilience is fixed

Multi-AZ, cross-Region DR and capacity for peak authorization stay. Savings come from commitments, right-sizing and non-prod, not from removing redundancy.

Records retention

Statements, transaction history and audit logs are kept for years but rarely read. Storage tiering is one of the biggest levers.

Seasonal peaks

Holiday spending and month-end statement runs spike volume. Commit to the steady baseline only and let autoscaling cover the peaks.

Fraud and risk ML

Model training and credit-risk batch jobs are bursty, so they suit Spot and scheduling. Real-time fraud scoring is latency-critical and is right-sized carefully.

Audit evidence

Policy as code gives auditors a versioned, tested record of every control and every exception, which manual reviews can't.

Grounded in Capital One experience

Capital One is one of the best-known all-in AWS banks, which makes it a useful reference point for how a card issuer runs cloud cost and governance at scale.

  • OPA/Rego policy as code. As a Cloud Security Architect there, I built OPA/Rego guardrails that the Security and Platform teams adopted. Step 03 applies the same pattern to cost.
  • Cloud Custodian. Capital One created and open-sourced this rules engine. Its tag-compliance and off-hours policies are a natural fit for the detective and corrective layers here.
  • Guardrails in the pipeline. In a regulated bank, controls that run on every change, with an audit trail, beat after-the-fact cleanup.

Talk trackCleanup is a one-time fix. Guardrails keep it fixed. These are the kinds of OPA/Rego policies I rolled out at Capital One, applied here to cost. OPA guards every deploy; Cloud Custodian, which Capital One created, enforces the same rules on resources that are already running.

Two policy engines, two moments

OPA (Open Policy Agent) is an open-source policy engine, a graduated CNCF project. Policies are written in Rego, a short declarative language: you describe what a violation looks like and OPA finds every match. Conftest is OPA's command-line tool for testing config files such as Terraform plans, Kubernetes YAML and Dockerfiles. A deny rule fails the build and a warn rule prints a warning but lets it continue.

Cloud Custodian is an open-source rules engine that Capital One created and donated to the CNCF. Policies are YAML. It runs as Lambda functions in every account (on a schedule or on CloudTrail events) and acts on resources that already exist: tag, notify, stop, start, snapshot, delete. OPA stops new waste before deploy. Custodian cleans up what is already running, including anything created outside Terraform.

Lower rate
Same servers, lower price
Commit to a steady amount of usage per hour for one or three years and AWS charges less for it. Nothing changes technically. Graviton lowers the rate by running on cheaper processors. Commit only to the 24/7 baseline, never to peaks.

    
Run smaller
Match size to real use
A server averaging 15% CPU drops one size in the same family, roughly halving its hourly price. Compute Optimizer recommends from CloudWatch data; the owning team approves the change.

    
Fewer hours
Non-prod sleeps at night
Cloud Custodian stops dev, test and UAT at 7pm and starts them at 7am on weekdays: 60 of 168 hours. A stopped server pays nothing for compute but still pays for its disks. RDS restarts itself after 7 days, so Custodian checks hourly.

    
Cheaper storage
Keep records, pay less
Statements and audit logs must be kept for years but are rarely read. Lifecycle rules move them to Glacier tiers without deleting anything, and retention locks stay. gp3 disks cost 20% less than gp2.

    
Cheaper network
Skip the NAT toll
Private servers reaching S3 through a NAT Gateway pay $0.045 per GB processed. A gateway endpoint carries the same traffic for free and keeps it on the AWS network.

    
Delete unused
Stop paying for leftovers
Disks attached to nothing and snapshots nobody needs. Custodian snapshots a disk before deleting it and skips anything under a retention hold.

  

  

    
What is never touched
Production keeps running around the clock. Multi-AZ, cross-Region DR and peak authorization capacity stay. Production gets cheaper only through rate and size, never by being turned off.

    
The one exception
A resource missing its required tags gets a notice and is stopped after 3 days if nothing changes. That is a governance control, aimed at stray dev resources, not a savings lever.

How Cloud Custodian runs
Open source · created by Capital One · CNCF

    



    

    
Policies live in Git and ship like code. c7n-org deploys each policy as a Lambda function into every account and Region. A schedule or a CloudTrail event triggers it; it lists matching resources, filters them by tags, age or CloudWatch metrics, then acts. Notifications go through one central mailer, and every run writes what it matched and changed to S3, which is how the dashboard counts actions and savings.

The math, worked
us-east-1 on-demand list prices

  

    
Hourly to monthly
$/hr × 730 = $/mo
AWS bills compute by the hour; 730 is the average hours in a month (8,760 ÷ 12).
c7i.8xlarge: $1.428 × 730 = $1,042
c7i.2xlarge: $0.357 × 730 = $261

    
Right-size savings
(old − new $/hr) × 730
Compute Optimizer suggests the new size from CloudWatch utilization; pricing comes from the price list.
8xlarge → 2xlarge: $1,042 − $261 = $781/mo
+ 500 GB gp2 → gp3: $50 − $40 = $10

    
Scheduling
1 − on hours ÷ 168
Non-prod runs 7am–7pm on weekdays instead of around the clock.
12 h × 5 days = 60 of 168 hours
Hours removed: 64% of non-prod compute

    
Storage
GB × price difference
gp3 is $0.08 vs gp2 $0.10 per GB-month. Glacier Instant Retrieval is $0.004 vs Standard $0.023.
gp2 → gp3 = 20% cheaper per GB
Standard → Glacier IR ≈ 83% cheaper per GB

    
Tag coverage
tagged $ ÷ total $
Measured on spend, not resource count, because one database matters more than a hundred tiny volumes.
$251.8k ÷ $412.8k = 61%
After tagging: $375.8k ÷ $412.8k = 91%

    
Unit cost
spend ÷ units × 1,000
The number leadership cares about. It shows whether growth is getting cheaper or more expensive per transaction.
$412.8k ÷ 160M × 1,000 = $2.58
After: $324.8k ÷ 160M × 1,000 = $2.03

Design principles

    

      
AWS-native first
Billing, metrics, events and enforcement use managed AWS services the bank already runs.

      
Open source for policy
OPA and Cloud Custodian keep rules portable and reviewable, with no vendor lock-in.

      
Everything as code
Infrastructure, policies and tests live in Git and change through pull requests.

      
Read-only by default
Analysis needs read access only. Custodian is the one component that acts, within narrow permissions.

About this demo
How the page itself is built

    
A single self-contained HTML file with inline CSS, JavaScript and SVG diagrams. It has no backend and makes no AWS calls: all figures are simulated constants, and the pipeline runs, policy outputs and savings math are computed in the browser. Tools are interchangeable where noted: GitLab CI, Jenkins or AWS CodePipeline can replace GitHub Actions, and QuickSight or Grafana can serve the dashboards.
